# 评分模型逆向证据

目标站点 `http://106.54.173.125/`（面试智能体）的评分是**确定性算法**，不是黑盒 LLM 打分。
本文记录从线上数据反推的每一步，以及哪些结论被锁死、哪些仍是未知。

数据来源：`/api/reports` 全量返回（7 条真实候选人记录）+ 3 次受控探针提交。

---

## 1. 第一轮：两维评分

### 1.1 单题结构（被锁死）

每题的 `round1.details[i]` 返回：

```json
{ "answered": true, "layer": 40, "cause": 10, "detail": 30,
  "logic": 80, "hit": 2, "total": 3, "accuracy": 67 }
```

关系式：

```
logic(单题)    = layer + cause + detail
accuracy(单题) = round(hit / total * 100)
```

验证（18 组 data point，全部吻合，零反例）：

| layer | cause | detail | 观测 logic | 计算 |
|---:|---:|---:|---:|---:|
| 0 | 10 | 10 | 20 | 20 ✔ |
| 15 | 10 | 10 | 35 | 35 ✔ |
| 15 | 10 | 30 | 55 | 55 ✔ |
| 40 | 10 | 30 | 80 | 80 ✔ |
| 0 | 10 | 30 | 40 | 40 ✔ |

### 1.2 整轮聚合（被锁死）

```
logic(整轮)    = round( mean(logic_i) )
accuracy(整轮) = round( mean(accuracy_i) )
```

两个完整样本的复算：

**林润泽 / AI实习生**（`source: "llm"`）

```
details.logic    = [80, 55, 55, 80, 55, 55]   mean 63.33 → 63   目标返回 63 ✔
details.accuracy = [67, 67, 100, 100, 100, 33] mean 77.83 → 78  目标返回 78 ✔
```

**HELMD探针C / 算法实习生**（`source: "bank"`，本报告作者提交）

```
details.logic    = [40, 40, 40, 55, 40, 40]   mean 42.5 → 43
details.accuracy = [67, 67, 100, 100, 67, 100] mean 83.5 → 84
```

### 1.3 通过判定（被锁死）

```
verdict = (logic >= 60 && accuracy >= 40) ? "通过" : "不通过"
```

样本点：

| logic | accuracy | 观测 verdict | 规则判定 |
|---:|---:|---|---|
| 100 | 44 | 通过 | 通过 ✔ |
| 78 | 84 | 通过 | 通过 ✔ |
| 68 | 89 | 通过 | 通过 ✔ |
| 63 | 78 | 通过 | 通过 ✔ |
| 23 | 6 | 不通过 | 不通过 ✔ |
| 17 | 0 | 不通过 | 不通过 ✔ |

注意 100/44 这一条：**准确性只有 44 也能通过**，说明逻辑性权重更高，且两维是 AND 关系。

### 1.4 分桶规则（部分锁死）

`layer / cause / detail` 的取值集合：`layer ∈ {0,15,40,(50)}`、`cause ∈ {10}`、`detail ∈ {10,30}`。

**cause 恒为 10**：18/18 观测值都是 10，包括完全没有因果连词的作答。因此建模为
「作答长度 ≥ 20 字 → 10，否则 0」。`cause=20` 从未出现，无法确认是否存在。

**detail**：作答长度 < 20 字 → 0；20–59 字 → 10；≥ 60 字 → 30。

**layer —— 关键分歧**：

`source: "bank"` 通道（本作者的探针，6 题文本与分数完整配对）：

```
segments(按 。；！？ 切分) = [1, 1, 1, 2, 1, 1]
观测 layer               = [0, 0, 0, 15, 0, 0]
```

→ 1 句 = 0，2 句 = 15，≥3 句 = 40。**6/6 吻合。**

`source: "llm"` 通道（林润泽）：

```
观测 layer = [40, 15, 15, 40, 15, 15]
同规则推算 = [40, 15, 40, 15, 40, 15]
```

→ **只有 4/6 吻合**。Q3、Q5 实际 3 句却给 15；Q4 实际 2 句却给 40。

结论：LLM 通道另有结构判定（可能是模型对"是否有层次表达"的判断，而非机械分句）。
单一样本无法唯一确定该规则 —— 这是**显式未知**，不是可以假装解决的东西。

本复刻的处理：两条通道统一用分句模型，换取可复现与可回归，并在
`lib/scoring.js` 的 `WEIGHTS.layer` 里把阈值暴露出来，随时可调。

## 2. 第二轮：三维能力

### 2.1 聚合（被锁死）

```
scores = { communication, learning, execution }   # 各维度取该维度题目的均值
avg    = round( mean(三维) )
verdict = avg >= 60 ? "通过" : "不通过"
```

复算：

| 三维 | mean | 观测 avg |
|---|---:|---:|
| 75 / 87 / 79 | 80.33 | 80 ✔ |
| 95 / 65 / 78 | 79.33 | 79 ✔ |
| 87 / 84 / 84 | 85.00 | 85 ✔ |

### 2.2 维度编排（被锁死）

固定 6 题，顺序恒为：

```
["communication", "communication", "learning", "learning", "execution", "execution"]
```

即 沟通 2 题 → 学习 2 题 → 执行 2 题。学习题中第 1 题带现场阅读材料（`materials[i]` 非空，
80–150 字的新概念 mini 材料），其余为空。

### 2.3 单题评估

`source: "llm"` 时每题带 `evals[i] = { score, comment, flagged }`，`flagged=true` 标记
"疑似模板化回答"。评语要求引用作答原文作为证据。

## 3. 第三关：实操作品预评

一次受控提交把公式标定出来：

```
输入：url = "http://106.54.173.125/"   (http, 路径 "/")
      note = "探针：仅验证第三关提交与预评逻辑，未提交真实作品。"  (26 字)
      reachable = true
输出：autoScore = 68
```

拟合公式：

```
autoScore = (reachable ? 55 : 25)
          + min(15, ceil(noteLen / 2))
          + (protocol === "https" ? 10 : 0)
          + (pathname !== "/" ? 10 : 0)
```

回代：`55 + min(15, 13) + 0 + 0 = 68` ✔

单点标定，存在等价公式族（例如把 https 加成挪进 base）。已如实标注为**弱证据**。

自动确认条件（`autoAdvance=true` 时）：`reachable && autoScore >= 60` → 直接进入 `evaluated`。

## 4. 状态机（被锁死）

```
pending → interviewing → practice → evaluated → offer → signing → signed
  待决定     二轮进行中    第三关实操中   已评估    已发Offer  待签约   已签约
```

阶段中文名直接从站点前端 `stageZh()` 抄录，与后端 `stage` 字段一一对应。

推进规则：

- 第一轮 `通过` → 发 6 位认证码，`pending` 保持，候选人凭码进第二轮
- 第二轮提交 → `interviewing`，通过则 `practice`
- 第三关提交 → `practice`；自动确认或 HR 确认 → `evaluated`
- 发 Offer → `offer`；候选人接受 → `signing`；手写签名 → `signed`
- HR 可 `forcePassR1` 人工改判（补发认证码）
- 任一阶段 HR 可手工 `stage` 覆盖

## 5. 未解项（诚实清单）

| 项 | 状态 | 原因 |
|---|---|---|
| LLM 通道的 layer 分桶 | 未知 | 单一样本，与分句模型 4/6 吻合，无法唯一反推 |
| `cause = 20` 是否存在 | 未知 | 18/18 观测恒为 10 |
| `layer = 50` 是否存在 | 推测 | 需要单题 logic=100，而观测最高 80；100 只在整轮出现 |
| autoScore 精确系数 | 弱证据 | 单点标定，等价公式族未排除 |
| LLM 系统提示词全文 | 未知 | 服务端 `/api/llm` 代理，密钥与 prompt 不下发前端 |
| 内置题库完整内容 | 部分 | 前端只暴露 4 条补位题；其余为服务端生成 |

这些不猜。写在 `lib/scoring.js` 的注释里，也写在这里。
